# Опция детализации тайлов при сохранении офлайн-региона — дизайн

**Дата:** 2026-06-12
**Статус:** утверждён

## Проблема

Офлайн-регион всегда качается в фиксированном диапазоне z0–14. Пользователь не может
выбрать ни более детальную карту (здания, дорожки, мелкая геометрия), ни лёгкую
версию для экономии места. При этом PMTiles-архив Protomaps содержит уровень z15 —
проверено вживую через `archive.getHeader()`: `{ minZoom: 0, maxZoom: 15 }`. Именно
на z15 лежит самая полная геометрия; глубже вектор просто растягивается без потери
чёткости линий.

## Решение (вариант A из обсуждения)

Пресет детализации выбирается на регион в sheet «Скачать регион» и прокидывается
через весь пайплайн: оценка размера → запись региона → загрузчик → стиль превью.
Ключевой факт: `downloadRegion` уже принимает `minZoom`/`maxZoom`
(`lib/offline/region-downloader.ts`) — параметры просто никто не передаёт.

Отвергнутые альтернативы:
- **Глобальная настройка качества** — опция спрятана, нельзя выбирать по ситуации,
  сантехника нужна та же.
- **Догрузка деталей постфактум** («Догрузить z15» в менеджере) — лучший UX для
  апгрейда, но добавляет состояния частичной детализации; возможное продолжение
  этой фичи, не первый шаг.

## Пресеты

| Пресет | maxZoom | UX-описание | Размер (пример Москвы, 721 тайл @ z14) |
|---|---|---|---|
| Экономия | 12 | контуры города, без зданий | ~3 МБ |
| Стандарт (дефолт) | 14 | как текущее поведение | ~32 МБ |
| Максимум | 15 | вся геометрия: здания, дорожки | ~120 МБ (≈4× стандарта) |

## UI — download-sheet

- Блок из трёх радио-карточек над блоком размера/квоты; на каждой — название,
  короткое описание и живой `≈ X МБ` от `estimateRegionSize(bbox, maxZoom)`.
- Блок размера, прогноз квоты и блокировка «превышает лимит 200 МБ» пересчитываются
  от выбранного пресета (вместо `payload.estimatedBytes` от триггера).
- Переключатель блокируется, когда `saveState` не `idle`/`error`.
- Кнопка-триггер на карте продолжает показывать оценку «Стандарта» — не трогаем.

## Данные и пайплайн

- `estimateRegionSize(bbox, maxZoom = 14)` — новый параметр.
- `OfflineRegion.maxZoom?: number` и `OfflineRegionInput.maxZoom?: number` —
  бессхемное поле, без бампа версии БД (прецедент — `routePoints`). Старые записи
  без поля читаются как 14.
- `useOfflineRegions().download(regionId, bbox, maxZoom?)` →
  `runDownload({ ..., maxZoom })`.
- `totalTilesPreview` в sheet → `countTiles(bbox, 0, selectedMaxZoom)`.

## Превью и стиль (критичная связка)

`buildOfflineStyle(regionId, theme, maxZoom = 14)`; превью передаёт
`region.maxZoom ?? 14`. `maxzoom` источника обязан совпадать с реально скачанным
диапазоном:

- «Экономия»: источник заявляет 12 → MapLibre растягивает z12-тайлы глубже
  (overzoom, вектор остаётся чётким). Если оставить 14 — при зуме >12 карта пустая.
- «Максимум»: источник заявляет 15 → настоящая детализация на больших зумах.

## Краевые случаи

- «Экономия» офлайн = без зданий (в z12-тайлах Protomaps слоя buildings нет) —
  честный трейд-офф, отражён в описании пресета.
- Регион «Экономии» покрывает bbox → триггер показывает «Доступно офлайн»;
  перекачать детальнее можно только удалив регион в менеджере. Осознанное
  ограничение (апгрейд — будущая фича).
- Отсутствующие в архиве тайлы (например, частично покрытый z15) пропускаются —
  уже текущее поведение `fetchTileBytes` → null.

## Тесты

Source-level файл `tests/server/offline-tile-detail.test.mjs` (стиль
`pwa-*.test.mjs`): эстиматор принимает maxZoom; в sheet есть пресеты, maxZoom
уходит в `add` и `download`; store сохраняет `maxZoom`; `buildOfflineStyle`
параметризован; превью передаёт `region.maxZoom`. Живая проверка через
preview-сервер: скачать «Экономию» и «Максимум», сравнить счётчики тайлов и
`maxzoom` источника в стиле карты.
